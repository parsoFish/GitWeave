# WI-10: I3b residuals #1-6

Target: `tests/test_i3b_residuals.py` (new, captures all 7 residual verifications); modifications to existing test files and `gitweave/self_serve/exceptions.py` and `gitweave/cli.py`.

## Residual #1: Membership endpoints text

The acceptance tests for add/remove membership name the current endpoints (`add_membership`, `remove_membership`). The code is NOT changed. Verify the test names match these endpoints and update any docstrings or comments that cited old endpoint names.

Coverage in `tests/test_self_serve_membership.py`: assert the endpoint strings `add_membership` / `remove_membership` appear in calls.

## Residual #2: Repo-scope idempotency

In `tests/test_self_serve_repo_scope.py`, extend the existing test:
- First run: assert the custom-property value was written (check the transport record)
- Second run with same inputs: assert zero write calls

## Residual #3: list-exceptions --team optional

In `gitweave/cli.py`, change `--team` from `required=True` to optional (no `required=True`) on the `list-exceptions` subparser:

```python
p_le.add_argument("--team", metavar="TEAM")  # optional
```

In `gitweave/self_serve/exceptions.py`, update `self_serve_list_exceptions` to accept `team=None`:
- Without `--team`: list every team's exceptions
- With `--team`: list that team's exceptions only

Update `tests/test_self_serve_exceptions.py` to cover both paths.

## Residual #4: add-member live test

In `tests/test_self_serve_membership.py`, add or update the add-member test:
1. Verify membership is absent before running command (GET /orgs/{org}/teams/{slug}/memberships/{user} → 404)
2. Run the command
3. Read membership back (GET → 200, role present)
4. Clean up (remove membership)

A no-op command stub must fail step 3 (membership not added → assertion fails).

## Residual #5: Per-repo CLI tests

In `tests/test_self_serve_repo_scope.py` (or the appropriate test file), for `update-content`, `add-member`, `add-exception`:
- Drive the real dispatch path (call `main()` via argparse or call the `cmd_*` function directly)
- Only fake the HTTP transport (not patch the whole function)

## Residual #6: Permission-check test

In `tests/test_cli_check_permission.py`, update the parser-enumeration test to include:
- `gw module render` (added in WI-3)
- `gw overlay apply` (added in WI-6)
- `gw overlay status` (added in WI-7)
- `gw overlay request` (added in WI-9)

The test enumerates subcommands from the live argparse parser (not a hardcoded list). A new subcommand without a permission check must fail the test.

## tests/test_i3b_residuals.py (new)

Class `TestI3bResiduals` that provides a concentrated test covering all 7 residuals' mutant-detection property:

- `test_permission_check_includes_i4_subcommands` — parses the live argparse tree; asserts the 4 new I4 subcommands are registered; asserts each has a permission-check path
- `test_membership_endpoint_names_match_code` — asserts `add_membership` / `remove_membership` strings appear in the self-serve membership implementation
- `test_repo_scope_idempotency_second_run_zero_writes` — stub scenario verifying second-run zero-write property
- `test_list_exceptions_team_optional` — drives `cmd_self_serve_list_exceptions` with `args.team=None`; asserts all-teams output; with `args.team="slug"`, asserts single-team output
- `test_add_member_from_absent_fails_if_noop` — no-op stub that skips the API write; asserts the readback step fails
- `test_per_repo_cli_update_content_drives_real_dispatch` — drives the full dispatch path for `update-content` with fake transport
- `test_no_pr_invariant_recording_transport_combined` — runs BOTH self-serve and overlay code paths through a shared RecordingTransport; asserts zero POST /repos/*/pulls

Tests must NOT inherit any GW_* autouse fixture.
